# Full-page account forms

Email and password settings now open as responsive full-page forms rather than small dialogs. Password fields sit beside the requirements on desktop and above them on phones. Email shows the current account address beside the new-address field on desktop and above it on phones. Both retain pending-value locks, validation, request recovery and the existing real API flow. The password reset option remains reachable, and its Back action is locked while sending so a delayed response cannot unexpectedly change recovery steps.

Open [local password settings](http://localhost:3001/settings/password) and [local email settings](http://localhost:3001/settings/email) as a signed-in account, with the frontend on 3001 and disposable API on 3200. Try an incorrect current password, retry with a disconnected API, then request a reset email. Fields retain values on failures. A new email request proceeds to the two-mailbox confirmation flow and does not change the address immediately. A failed email request gives retry guidance; HTTP 400 does not prove that another account owns the address. Better Auth deliberately returns a neutral 200 for existing addresses.

The wrong-password banner and field message match the designed error placement. Its description says to check the current password rather than inventing a remaining-attempt count: the API's five-attempt lockout is a sign-in policy, not a password-change budget. The unused misleading translation was removed.
