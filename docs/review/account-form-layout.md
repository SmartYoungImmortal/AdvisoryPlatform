# Full-page account forms

Email and password settings now open as responsive full-page forms rather than small dialogs. Password fields sit beside the requirements on desktop and above them on phones. Email shows the current account address beside the new-address field on desktop and above it on phones. Both retain pending-value locks, validation, request recovery and the existing real API flow. The password reset option remains reachable, and its Back action is locked while sending so a delayed response cannot unexpectedly change recovery steps.

Open [local password settings](http://localhost:3001/settings/password) and [local email settings](http://localhost:3001/settings/email) as a signed-in account, with the frontend on 3001 and disposable API on 3200. Try an incorrect current password, retry with a disconnected API, then request a reset email. Fields retain values on failures. A new email request proceeds to the two-mailbox confirmation flow and does not change the address immediately. A failed email request gives retry guidance; HTTP 400 does not prove that another account owns the address. Better Auth deliberately returns a neutral 200 for existing addresses.

The wrong-password banner and field message match the designed error placement. Its description says to check the current password rather than inventing a remaining-attempt count: the API's five-attempt lockout is a sign-in policy, not a password-change budget. The unused misleading translation was removed.

Verdict: differences remain. The form composition, 800px desktop card and field/requirements layout follow the reference, but the existing shared rail/theme replaces its header/footer and colors. Those other-owner components are unchanged. Email omits the reference password field because the API confirms through both mailboxes and accepts no password here; the copy describes that actual contract. Password keeps a reset link and a desktop Cancel action. Verification/reset-result dialogs remain existing layouts. Native OS status/home indicators are not fabricated. The SVG mail, lock and circle-check assets are exact Figma downloads with their intrinsic 16, 18 and 14px sizes verified in the real browser. Side-by-side comparisons use matching 402x874 phone and 1440px desktop viewports.

All ten focused integrated scenarios pass: two-mailbox email changes, actual password update/reset, profile saves, pending locks, wrong-password recovery and deletion. A held real reset-email 200 verifies that Send and Back stay disabled. Only the failed email configuration response and disconnected password retry are deliberately injected; all successful responses use the actual API. No browser page errors. Expected console responses are missing-avatar 404s rendered as initials and deliberate wrong-password 400s; no other failed responses were found in the visual proof. Build, lint and type checks pass. Media stays outside Git.

Request failures keep generic retry guidance. No API contract or shared-owner screen is changed.
