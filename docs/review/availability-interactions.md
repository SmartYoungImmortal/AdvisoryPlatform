# Availability: time menu and date dialog

Advisors can open the end-time menu directly in the real editor. Options show duration from the actual start, stay within the same day and update the saved end time. Selection and Escape close the accessible, portalled menu without clipping it inside a day card.

The add-date dialog now traps focus, supports multiple time ranges, shows validation and request failures inside the dialog, preserves values for retry and returns to the specific-date editor after saving. Adding another range for an existing date preserves earlier ranges and rejects overlaps. Cancel does not save. Pending controls are disabled. The stale, unrequested daily-duration badge was removed: it stayed at the persisted total after edits and was absent from Figma. Editing clears stale error/success messages.

Open [local availability profiles](http://localhost:3001/availability/profiles) as an advisor with the disposable frontend on 3001 and API on 3200. Edit an owned profile: open the end-time arrow, select a later time, save and refresh. Open Specific dates, choose Add specific date, try a backwards range, correct it, add another range and save. Expect the dialog to close and both ranges to survive refresh. Repeat for the same date with a non-overlapping range; the earlier ranges remain. Overlap, disconnected-API retry and Cancel are covered too.

Run `AVAILABILITY_LIVE_PROOF=1 pnpm exec playwright test tests/e2e/availability-interactions-live.spec.ts tests/e2e/availability-live.spec.ts`. Four integrated phone/desktop scenarios pass against the real API. The new interaction scenario failed before the fix because the normal editor had no time-menu trigger. No successful response is mocked. Only the disconnected request is deliberately injected. Fixtures are isolated synthetic profiles and cleaned up. Browser page errors are absent. The full 69-scenario run passed, then the four affected scenarios passed again after removing the stale badge and clearing errors on edits. All 107 frontend unit tests pass; lint, type checks and production build pass.
